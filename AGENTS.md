# Работа с isobox

## Roadmap

- Перед выбором задачи читай `ROADMAP/ARCHITECTURE.md`, `TASK.md`, `CONTEXT.md`, `QA.md` соответствующей feature-группы и документы зависимостей.
- За один запрос выполняй ровно одну задачу, выбранную пользователем. Начинай её только при закрытых зависимостях; не расширяй scope на соседние задачи.
- После реализации обновляй статус задачи, технические решения в `CONTEXT.md` и фактически выполненные проверки в `QA.md`. Не отмечай незапущенные проверки успешными.
- Сохраняй согласованные границы безопасности: профиль валидируется до запуска; обязательные mounts, сетевые ограничения и лимиты применяются fail-closed. Не ослабляй их молча и не запускай приложение, если обязательное ограничение не удалось применить.

## Структура и команды

- Go CLI: `cmd/isobox/`; код — в `internal/cli`, `profile`, `preflight`, `sandbox`, `proxy`, `limits`, `integration`.
- Roadmap и критерии приёмки: `ROADMAP/`. Host/runtime runners и их предпосылки описаны в `tests/README.md`; список доступных сценариев — `./tests/run.sh --list`.
- `go.mod` задаёт модуль `github.com/arwos/isobox` и Go `1.26.8`. Форматируй изменённые Go-файлы через `gofmt -w <файлы>`.
- Из корня репозитория доступны `go build ./...`, `go test ./...` и `go vet ./...`; в QA для ограниченного окружения применялись `GOCACHE=/tmp/isobox-gocache GOMODCACHE=/tmp/isobox-gomodcache GOPATH=/tmp/isobox-gopath` перед командами Go.
- Makefile определяет `make build` (goppy), `make lint` (`goppy lint`), `make tests` (`goppy test`) и `make pre-commit` (устанавливает `goppy@latest`, затем license/lint/tests/build). Не запускай `make pre-commit` без необходимости: цель устанавливает latest tool и может менять файлы. CI workflow сейчас только настраивает Go и не содержит шагов сборки или тестов.
- Базовые сборка и тесты не заменяют runtime-приёмку. Запускай только релевантный runner из `tests/README.md`, от обычного пользователя, без `sudo`; сетевые, desktop, Podman и systemd/cgroup сценарии требуют перечисленных там возможностей. Отражай в `QA.md` реальные результаты и ограничения среды.

## Изменения и безопасность

- Сохраняй разделение: профиль описывает sandbox, команду приложения передаёт пользователь после `--`.
- Для сети и sandbox следуй действующим решениям `ROADMAP/ARCHITECTURE.md`, включая IPv4-only и fail-closed поведение; сначала проверь соответствующие зависимости и критерии приёмки.
- Не включай несвязанные пользовательские изменения в commit. Для реализации используй формат `<TASK-ID>: <краткое название>`.
