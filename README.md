# isobox

`isobox` запускает Linux-приложения в изолированной среде на базе [bubblewrap](https://github.com/containers/bubblewrap). Профиль задаёт доступ к файлам, сети, графической сессии и ресурсам и может содержать команду приложения по умолчанию; пользователь может переопределить её аргументами после `--`.

## Возможности

- Минимальная файловая среда с системными каталогами только для чтения и явными профильно заданными mounts.
- Изолированный `HOME`: существующий каталог можно указать в профиле; иначе сохраняемый каталог создаётся под `/tmp` и привязывается к `--app-id`.
- Сетевые режимы `off`, `direct`, `proxy` и `egress`. Сеть работает только по IPv4; опубликованы могут быть только явно заданные входящие порты.
- `proxy` передаёт TCP и UDP через внешний SOCKS5-сервер. `egress` использует встроенную IPv4 policy: доступ наружу получают только явно разрешённые IP/CIDR, порты и протоколы.
- Отдельные разрешения Wayland, X11, audio, GPU и пользовательской session D-Bus.
- Ограничения CPU, памяти, числа задач и открытых файлов, если их поддерживает хост.
- Переменные окружения задаются явно в профиле; host environment очищается перед запуском приложения.
- Профиль по умолчанию создаётся при первом запуске без `--profile`; доступны необязательные пользовательские desktop launchers и systemd user units.
- Команда `isobox ps` показывает таблицу запущенных через isobox приложений, их PID, app-id, рабочую папку, память, CPU и режим сети.

## Требования

- Linux с включёнными user namespaces.
- Go `1.26.8` для сборки из исходников.
- `bubblewrap` (`bwrap`). Режим `direct` требует `pasta` или совместимый `slirp4netns`; `proxy` и `egress` требуют доступный `/dev/net/tun`. Для `proxy` также настройте SOCKS5 alias.
- Для `off`, `proxy` или `egress` с опубликованными портами нужны `pasta` и `nft`. Для лимитов CPU/памяти/процессов нужны cgroup v2 и пользовательский `systemd-run`.

Некоторые возможности зависят от настроек ядра, пользовательской сессии и установленных программ. isobox не устанавливает системные зависимости и прекращает запуск, если не может применить обязательное ограничение.

Sandbox также создаёт отдельный cgroup namespace, чтобы приложение видело только виртуализованный путь своей cgroup. Ограничения CPU, памяти и числа задач по-прежнему устанавливаются через пользовательский `systemd-run` scope и проверяются isobox до старта приложения.

## Установка через go install

При установленном Go `1.26.8` или новее установите последнюю версию CLI:

```sh
go install github.com/arwos/isobox/cmd/isobox@latest
```

Go поместит бинарный файл в каталог `GOBIN`, если он задан, иначе в `$(go env GOPATH)/bin`. Убедитесь, что этот каталог есть в `PATH`, затем проверьте установку:

```sh
isobox help
```

`go install` устанавливает только isobox. Системные зависимости, включая `bubblewrap` и сетевые backend-ы, устанавливаются отдельно.

## Сборка

```sh
git clone https://github.com/arwos/isobox.git
cd isobox
go build -o isobox ./cmd/isobox
```

Проверьте доступность CLI:

```sh
./isobox help
```

## Быстрый старт

Создайте файл `minimal.unic`:

```unic
version 1;

network {
  mode off;
}
```

Запустите приложение, передав команду после `--`:

```sh
./isobox run --app-id=demo -- /usr/bin/true
```

Команда ищет `demo.unic` в пользовательском каталоге конфигурации, а если файла нет — использует профиль по умолчанию. Чтобы запустить созданный выше `minimal.unic`, укажите его явно:

```sh
./isobox run --profile=./minimal.unic --app-id=demo -- /usr/bin/true
```

Чтобы посмотреть рассчитанные параметры запуска, не запуская приложение, используйте `config` с теми же флагами и командой:

```sh
./isobox config --profile=./minimal.unic --app-id=demo -- /usr/bin/true
```

Команда выводит таблицу с эффективным профилем, окружением, сетевым backend, лимитами, egress log path для режима `egress` и полным списком аргументов bubblewrap. Она выполняет проверку профиля и host preflight, но не запускает приложение.

Все аргументы после `--` передаются приложению как есть и заменяют `command` из профиля. Если команда после `--` не указана, запускается команда из профиля; если обе команды отсутствуют, isobox сообщает об ошибке. Без `--app-id` можно запускать профиль с заданным `home_path`; иначе `--app-id` задаёт постоянный HOME в `~/.isobox/home/<app-id>/`.

Приложение запускается с рабочим каталогом `/home/isobox` внутри sandbox; переменная `PWD` также устанавливается в `/home/isobox`.

Для `direct`, `proxy` и `egress` можно задать имя сетевого интерфейса и IPv4-подсеть:

```unic
network isobox0 10.10.10.1/24 {
  mode direct;
}
```

Оба позиционных значения необязательны: `network isobox0 { ... }` задаёт только имя, а `network 10.10.10.1/24 { ... }` — только подсеть. При заданной подсети isobox случайно выбирает адрес контейнера из host-адресов подсети. В `direct` через pasta случайно выбирается и отдельный gateway. В `proxy` и `egress` адреса контейнера, DNS и host gateway выбираются отдельно из той же подсети; поэтому `host.gateway.internal` всегда указывает на виртуальный gateway в настроенной сети. Без подсети используются прежние DNS `10.89.0.2` и host gateway `10.89.0.3`. Для пользовательской сети в `direct` требуется pasta с поддержкой `--ns-ifname`, а при заданной подсети — также `--address`, `--netmask` и `--gateway`; запуск через slirp4netns в этом случае завершается ошибкой до старта приложения. Адреса интерфейса, DNS и gateway видны в таблице `isobox config`.

По умолчанию внутри sandbox сохраняются текущие эффективные host UID/GID, а пользователь и основная группа называются `isobox`. Host `/etc/passwd` и `/etc/group` не подключаются. Профиль может задать guest UID/имя и несколько групп: UID пользователя и GID первой группы отображаются на запускающего isobox host-пользователя. Остальные группы добавляются в приватный `/etc/group` как дополнительные account-записи; они не становятся supplementary GID процесса и сами по себе не дают доступ к host-файлам или устройствам.

В UTS namespace контейнера hostname задаётся как `isobox-<app-id>`. Без `--app-id` используется `isobox`. В `/etc/hosts` контейнера `localhost` и это hostname указывают на `127.0.0.1`, то есть на loopback самого sandbox. Так как Linux ограничивает hostname 64 байтами, слишком длинный app-id для hostname обрезается до 57 байт; сам app-id и путь managed HOME не меняются.

## Профиль

Файл профиля использует формат UNIC. Пример разрешает приложению чтение каталога `/opt/my-app/data`, задаёт отдельный `HOME` и включает только Wayland:

```unic
version 1;
user 1000 alice;
group 1000 alice;
group 44 video;
home_path '/home/alice/.local/share/my-app';
command ['/usr/bin/my-app', '--safe-mode'];

env (TERM, 'xterm-256color');
path ['/opt/my-app/data/bin'];

mount {
  source '/opt/my-app/data';
  target '/opt/my-app/data';
  read_only true;
}

network {
  mode off;
}

gui {
  wayland true;
}
```

Все параметры профиля:

| Путь | Тип и допустимые значения | По умолчанию и ограничения |
| --- | --- | --- |
| `version` | целое число | `1`; другие версии отклоняются |
| `user` | одна запись `user UID NAME;`, например `user 1000 alice;` | если не задана, UID запускающего пользователя и имя `isobox`; UID — целое `0–4294967294`, имя — до 32 символов `[a-z_][a-z0-9_-]*` |
| `group` | повторяемая запись `group GID NAME;`, например `group 1000 alice; group 44 video;` | если не задано, GID запускающего пользователя и имя `isobox`; первая запись — primary GID процесса, последующие есть только в `/etc/group`; GID — целое `0–4294967294`, имена проверяются как для `user`; повторяющиеся имена/ID запрещены |
| `command` | список строк: исполняемая программа и аргументы, например `command ['/usr/bin/my-app', '--safe-mode'];` | не задана; используется, если команда не передана после `--`; пустой список требует команды в CLI |
| `home_path` | абсолютный путь к каталогу на хосте | не задан; `/` запрещён, каталог должен быть доступен при запуске |
| `env` | map строковых имён и значений, например `env (TERM, 'xterm-256color');` | пустой; host environment очищается. Имя должно соответствовать `[A-Za-z_][A-Za-z0-9_]*`; NUL в значениях запрещён. `HOME`, `PATH`, `PWD`, `TMPDIR`, `GOMAXPROCS` зарезервированы |
| `path` | список абсолютных каталогов внутри sandbox, например `path ['/opt/my-app/data/bin'];` | пустой; элементы добавляются в начало встроенного sandbox `PATH`, host `PATH` не наследуется; каталог должен быть доступен в sandbox (например, подключён через `mount`); `:` в элементах запрещён |
| `mount` | повторяемый блок | нет mounts по умолчанию; см. поля ниже |
| `mount.source` | абсолютный путь к источнику на хосте | обязателен; `/` запрещён, существование и доступность проверяются при запуске |
| `mount.target` | абсолютный путь внутри sandbox | обязателен; `/` запрещён; цели mounts должны быть уникальны |
| `mount.read_only` | `true` или `false` | `true`; для записи нужно явно указать `false` |
| `network.mode` | `off`, `direct`, `proxy`, `egress` | `off`; пустое значение наследует встроенный `off` |
| `network` позиционное значение 1 | имя интерфейса (до 15 ASCII символов) или IPv4 CIDR, например `network isobox0 { ... }` или `network 10.10.10.1/24 { ... }` | необязательно; `lo` и некорректные имена отклоняются; CIDR в первом значении означает, что имя не задано |
| `network` позиционное значение 2 | IPv4 CIDR, например `10.10.10.1/24` | необязательно; применяется с режимами `direct`, `proxy`, `egress`; для custom network в `direct` нужен совместимый pasta |
| `network.dns` | повторяемый IPv4-адрес без порта; порядок задаёт очередность upstream, например `dns 1.1.1.1; dns 1.0.0.1;` | profile-список целиком заменяет `settings.defaults.dns`; без списка `direct` использует DNS backend-а, `proxy` — первый IPv4 resolver хоста, `egress` не использует host resolver (явный global default применяется) |
| `network.proxy_alias` | alias SOCKS5 | обязателен при `mode proxy`; запрещён с `off`, `direct` и `egress` |
| `network.proxy.allow` | повторяемый блок правил доступа к IPv4/CIDR | в `egress` пустой список блокирует весь исходящий трафик; в `proxy` список необязателен и фильтрует назначения до SOCKS5 |
| `network.proxy.allow.ip` | один или несколько IPv4-адресов/CIDR; поле можно повторять или задать списком, например `ip ['8.8.8.8/24', '1.1.1.1/24'];` | обязателен хотя бы один адрес; IPv6 запрещён |
| `network.proxy.allow.port` | список портов `1–65535`, например `[443, 8443]`; одиночное `port 443;` тоже поддерживается | не задан — разрешены все порты совпавшего IP/CIDR |
| `network.proxy.allow.port_range` | повторяемая запись `port_range START END;`, например `port_range 8080 8090;` | не задан; диапазоны включительные и объединяются со списком `port` |
| `network.proxy.allow.port_range` значение 1 | начальный порт `1–65535` | обязателен |
| `network.proxy.allow.port_range` значение 2 | конечный порт `1–65535` | обязателен; не меньше начального |
| `network.proxy.allow.protocol` | `both`, `tcp`, `udp` | `both` |
| `network.resolver.record` | повторяемый блок с доменом первым позиционным атрибутом, например `record service.example { ... }` | в `egress` A-записи отвечаются локально и имеют приоритет над upstream |
| `network.resolver.record.ip` | один или несколько IPv4-адресов; поле можно повторять или задать списком | обязателен хотя бы один адрес; IPv6 запрещён; максимум 16 уникальных адресов на домен |
| `network.port` | повторяемая запись `port HOST_ADDRESS PORT [PROTOCOL [END_PORT]];` | порты закрыты, пока записи явно не заданы |
| `network.port` значение 1 | IPv4 bind-адрес хоста | обязателен; IPv6 запрещён |
| `network.port` значение 2 | порт `1–65535` | обязателен; является портом и на хосте, и в sandbox |
| `network.port` значение 3 | `both`, `tcp`, `udp` | `both`; можно опустить |
| `network.port` значение 4 | конечный порт `1–65535` | не задан; задаёт включительный конец диапазона, не меньше второго значения |
| `gui.wayland` | `true` или `false` | `false` |
| `gui.x11` | `true` или `false` | `false` |
| `gui.audio` | `true` или `false` | `false` |
| `gui.gpu` | `true` или `false` | `false` |
| `gui.desktop` | `true` или `false` | `false`; разрешает пользовательскую session D-Bus |
| `limits.cpu_quota_percent` | положительное число процентов CPU; `100` = один логический CPU | `0` или поле отсутствует — лимит не запрошен |
| `limits.memory_bytes` | объём памяти в байтах | `0` или поле отсутствует — лимит не запрошен |
| `limits.process_count` | число задач, включая потоки | `0` или поле отсутствует — лимит не запрошен |
| `limits.open_files` | число открытых файловых дескрипторов | `0` или поле отсутствует — лимит не запрошен |

## Сетевые режимы

Все режимы работают в IPv4-only namespace. Входящие порты закрыты, пока их явно не объявили через `network.port`.

### `off`

| Параметр | Поведение |
| --- | --- |
| Исходящий трафик | Закрыт к Интернету, LAN и host. Loopback доступен только внутри sandbox. |
| Входящие порты | Только явные `network.port <IPv4 host address> <port> [protocol [end_port]]`; нужны `pasta` и `nft`. Ответы принятых соединений разрешены. |
| DNS и IPv6 | Внешнего DNS нет; IPv6 отключён. |
| Имя интерфейса и CIDR | Не поддерживаются. |

### `direct`

| Параметр | Поведение |
| --- | --- |
| Исходящий трафик | Rootless IPv4-сеть через `pasta` или совместимый `slirp4netns`; IP allowlist не применяется. |
| DNS | IPv4 DNS из `network.dns` или DNS выбранного backend-а. IPv6 DNS не поддерживается. |
| Входящие порты | Только явные `network.port`; автоматическое пробрасывание отключено. |
| Имя интерфейса и CIDR | Можно задать оба атрибута по отдельности. Из CIDR случайно выбираются адрес контейнера и отдельный gateway. Нужен совместимый `pasta`; `slirp4netns` не используется для пользовательской сети, так как назначает гостевой IP самостоятельно. |

### `proxy`

| Параметр | Поведение |
| --- | --- |
| Исходящий трафик | Обязателен `network.proxy_alias`. TCP и UDP проходят через внешний SOCKS5; direct fallback отсутствует. |
| DNS | Запросы проходят через тот же SOCKS5. По умолчанию используется первый IPv4 resolver хоста; можно задать `network.dns`. Если задан `network.proxy.allow`, он должен разрешать IP DNS-сервера и порт 53. |
| Фильтрация | `network.proxy.allow` необязателен; если задан, ограничивает назначения по IPv4/CIDR, портам и протоколам до SOCKS5. |
| Входящие порты | Явные `network.port` проходят через guarded `pasta` ingress; нужны `pasta` и `nft`. |
| Имя интерфейса и CIDR | Можно задать по отдельности. При CIDR адрес контейнера, DNS endpoint и gateway случайно выбираются раздельно из подсети. Без CIDR используются интерфейс `isobox0`, адрес `10.89.0.1/24` и DNS endpoint `10.89.0.2`. |
| ICMP и IPv6 | TUN поддерживает только IPv4 TCP/UDP; IPv6, ICMP и raw IP не проходят. `ping` не проверяет доступность сети или SOCKS5. |

### `egress`

| Параметр | Поведение |
| --- | --- |
| Исходящий трафик | Встроенный TUN напрямую подключается к разрешённым IPv4 назначениям. Пустой `network.proxy.allow` закрывает весь egress; SOCKS5 alias не используется. |
| Allowlist | Правила задают IP/CIDR и необязательные порты/диапазоны с протоколом `tcp`, `udp` или `both`. Блокировка выполняется до host-side dial. |
| DNS | `network.resolver.record` обслуживается локально. Неизвестные имена идут только на заданный `network.dns`; для каждого upstream нужен allow-rule на порт 53. Без upstream неизвестные имена не разрешаются. Зарезервированное `host.gateway.internal` локально возвращает A-запись gateway и NODATA для AAAA/прочих типов. |
| Host loopback | `/etc/hosts` сопоставляет `host.gateway.internal` с виртуальным gateway. Чтобы подключиться к host loopback, отдельно разрешите целевой `127.0.0.1`, порт и протокол. Gateway отображается в `isobox config`; без пользовательской подсети это `10.89.0.3`. |
| Входящие порты | Явные `network.port` проходят через guarded `pasta` ingress; нужны `pasta` и `nft`. |
| Имя интерфейса и CIDR | Можно задать по отдельности. При CIDR адрес контейнера, DNS endpoint и gateway случайно выбираются раздельно из подсети. Без CIDR используются `isobox0`, `10.89.0.1/24`, DNS `10.89.0.2` и gateway `10.89.0.3`. |
| ICMP и IPv6 | TUN поддерживает только IPv4 TCP/UDP; IPv6, ICMP и raw IP не проходят. `ping` не проверяет доступность gateway. |

Профильный mount не может перекрывать служебные `/etc/hosts` и сетевой `/etc/resolv.conf`. Профильная `command` — это массив argv, не shell-строка: isobox не запускает shell автоматически.

В `egress` ошибки DNS-разрешения и заблокированные назначения записываются в `~/.isobox/log/<app-id>.log`; если app-id не задан, используется `~/.isobox/log/default.log`. Каталоги создаются с правами `0700`, файл — `0600`. События содержат домен либо IP, порт/протокол и причину блокировки, без содержимого трафика. Если файл недоступен, isobox сообщает об этом в stderr и продолжает запуск с той же сетевой политикой.

Пример `egress` с несколькими разрешёнными сетями, отдельными портами и диапазоном, а также статической DNS-записью:

```unic
network {
  mode egress;
  dns 1.1.1.1;
  dns 1.0.0.1;
  proxy {
    allow {
      ip '203.0.113.10';
      ip '198.51.100.0/24';
      port [443, 8443];
      port_range 9000 9100;
      protocol tcp;
    }
    allow {
      ip '1.1.1.1';
      ip '1.0.0.1';
      port 53;
      protocol both;
    }
  }
  resolver {
    record service.example {
      ip '203.0.113.10';
      ip '203.0.113.11';
    }
  }
}
```

Пример публикации одного TCP-порта на loopback хоста:

```unic
network {
  mode off;
  port 127.0.0.1 8080 tcp;
  port 127.0.0.1 8081 tcp;
}
```

Сетевые разрешения не расширяются автоматически: в частности, не объявленные входящие порты закрыты, IPv6 отключён.

## SOCKS5

Добавьте alias прокси. При `userpass` программа запросит имя и пароль в терминале; они не передаются через аргументы командной строки.

```sh
./isobox proxy add --alias=work --server=proxy.example:1080 --auth=userpass
./isobox proxy list
```

Укажите alias в профиле:

```unic
network {
  mode proxy;
  proxy_alias 'work';
}
```

Хранилище прокси находится в пользовательской конфигурации и ограничено правами доступа. SOCKS5 не шифрует логин, пароль или трафик приложения: используйте только доверенную сеть или защищённый транспорт к прокси. Удаление alias: `./isobox proxy remove --alias=work`.

## Именованные групповые сети

Создайте постоянную rootless bridge-сеть с подсетью IPv4:

```sh
./isobox network create --name=backend --subnet=192.168.40.0/24
./isobox network list
./isobox network remove --name=backend
```

В качестве подсети можно указать адрес с CIDR, например `192.168.40.1/24`; isobox использует всю подсеть и сохраняет её канонический вид `192.168.40.0/24`. Поддерживаются префиксы `/8`—`/29`; первый доступный адрес резервируется bridge как gateway. Описание сети хранится в `~/.isobox/networks/`, а bridge создаётся и удерживается отдельным пользовательским `systemd --user` service. `create` завершается успешно только после готовности bridge; `list` показывает состояние manager и число интерфейсов участников; `remove` отказывает, пока к bridge подключены участники.

Нужны Linux с rootless user/network namespaces и работающий пользовательский systemd manager. При входе пользователя manager автоматически запускает созданные сети. Для запуска user manager до интерактивного входа требуется systemd lingering; isobox не включает его автоматически. Сейчас эти команды управляют самим bridge; подключение sandbox через профильные `group` настраивается следующим этапом F09.

## Профиль по умолчанию и desktop launcher

Без `--profile` isobox сначала ищет профиль `~/.isobox/config/<app-id>.unic`. Если `--app-id` не задан или файл `<app-id>.unic` отсутствует, используется `~/.isobox/config/default.unic`. При первом запуске без подходящего файла `default.unic` создаётся с правами `0600` и безопасным режимом сети `off`:

```unic
version 1;
network {
  mode off;
}
```

Измените `~/.isobox/config/default.unic`, чтобы задать разрешения, `env` и дополнения `path` по умолчанию. Для приложения можно создать отдельный файл `~/.isobox/config/my-app.unic` для `--app-id=my-app`; он полностью заменяет `default.unic`, а параметры из двух файлов не объединяются. Если передан `--profile`, используется только указанный профиль; автоматический поиск профиля не выполняется. `XDG_CONFIG_HOME` на каталог профилей не влияет. Профили из прежнего `~/.config/isobox/` и managed HOME из `/tmp/isobox-<uid>/` автоматически не переносятся.

Можно установить или удалить пользовательский desktop launcher:

```sh
./isobox integration desktop install \
  --id=my-app --name='My App' --profile=/home/alice/.config/isobox/my-app.unic \
  --app-id=my-app -- /usr/bin/my-app
./isobox integration desktop remove --id=my-app
```

### Пользовательский systemd service

Установите unit для команды `command`, заданной в профиле:

```sh
./isobox integration systemd install --profile=/home/alice/.config/isobox/my-app.unic --app-id=my-app
```

Установка завершается ошибкой, если в профиле нет `command`. Unit сохраняется в `$XDG_CONFIG_HOME/systemd/user/` (по умолчанию `~/.config/systemd/user/`) и перезагружает пользовательский systemd manager. Установка не включает и не запускает service. Управляйте автозапуском так:

```sh
./isobox integration systemd enable --app-id=my-app
./isobox integration systemd disable --app-id=my-app
```

`enable` включает запуск при старте пользовательского `default.target`, но не запускает service сразу. Для запуска или остановки текущего процесса используйте `systemctl --user start/stop isobox-my-app.service`. `disable` выключает автозапуск, не останавливая уже запущенный service. Удаление останавливает и отключает принадлежащий isobox unit перед удалением файла:

```sh
./isobox integration systemd remove --app-id=my-app
```

## Список запущенных приложений

```sh
./isobox ps
```

Команда выводит таблицу `PID`, `APP-ID`, `WORKING DIRECTORY`, `MEMORY`, `CPU` и `INTERNET`. Память и CPU относятся к PID приложения; CPU измеряется за короткий интервал при вызове `ps`. `INTERNET` показывает режим сети профиля (`off`, `direct`, `proxy` или `egress`), а не проверку доступности внешнего адреса. Запуски, начавшиеся до установки этой версии, в список не входят.
