# F04 Контекст

- Bubblewrap создаёт пустой mount namespace/root и собирает доступы из опций запуска. Это низкоуровневый механизм; изоляционную политику полностью задаёт вызывающий isobox.
- Базовые системные runtime-каталоги — read-only; нестандартные host paths только из профиля.
- `HOME` задаётся профилем как host path; существующий каталог монтируется в `/home/isobox` и не меняется isobox. При отсутствии `home_path` каталог создаётся в `/tmp/isobox-<uid>/<sha256(profile-path, app-id)>`, сохраняется между запусками и имеет режим `0700`; `--app-id` обязателен только для такого управляемого HOME. Профиль идентифицируется каноническим путём. Очистка `/tmp` ОС может удалить данные.
- GUI-доступ задаётся вручную и отдельно; полного D-Bus и portal integration нет по умолчанию.
- F04-T01 собирает root только из `/usr` (обязательный) и существующих `/bin`, `/sbin`, `/lib`, `/lib64`; доверенные каталоги сертификатов и отдельные runtime-файлы `/etc` подключаются read-only. Весь `/etc`, host root и host home не монтируются. Любой выбранный `--ro-bind` остаётся обязательным для bwrap: ошибка bind завершает запуск.
- В sandbox создаются отдельные `/proc`, `/dev`, `/tmp`, `/run`, `/var/tmp`; рабочий каталог фиксирован на `/`. Окружение очищается и получает только внутренние `PATH`, `HOME=/home/isobox`, `TMPDIR=/tmp`, `PWD=/`. `--unshare-user`, `--unshare-pid`, `--unshare-ipc`, `--unshare-uts`, `--unshare-net` обязательны; поэтому базовый режим сети здесь `off`.
- Пользовательские mounts разрешают только существующие обычные файлы и каталоги, запрещают host root, специальные файлы и runtime targets `/proc`, `/dev`, `/tmp`, `/run`, `/var/tmp`, `/root`, `/home`, `/home/isobox`, `/run/isobox/**` и `/tmp/.X11-unix/**`. Read-only mount превращается в `--ro-bind`, writable — в `--bind`; mount-ошибки bwrap блокируют payload. Пути сортируются по глубине, поэтому родительские mounts применяются раньше вложенных, а дочерние пути внутри HOME — после HOME. `home_path` должен указывать на существующий каталог, не на host root; он монтируется доступным приложению на запись.
- Для управляемого HOME `/tmp` должен быть настоящим каталогом со sticky bit. Приватный родитель каталога принадлежит текущему UID и имеет режим `0700`, поэтому приложение не может открыть его для других пользователей, даже если поменяет права самого HOME. Для обычных профилей с explicit HOME флаг `--app-id` не нужен. Профиль без `home_path` и без `--app-id` отклоняется до запуска.
- Runtime runner `tests/f04-sandbox/base-runtime/run.sh` проверяет минимальный root, `/proc`, `/dev`, tmpfs для `/tmp`, `/run` и `/var/tmp`, отсутствие host root/home и не подключённых путей, очищенное приложение environment, невозможность записи в system mounts, точные argv/exit status и пересылку SIGTERM. Отказ обязательного `/usr` bind проверяется временным bwrap shim, который делегирует реальные `--version`/`--help` и preflight probe, затем отказывает только на launch-команде; payload marker должен остаться отсутствующим. Отчёт доступен через `./tests/run.sh f04-base-runtime`.
- Runtime runner `tests/f04-sandbox/run.sh` проверяет точный writable `home_path`, реальное read-only/writable поведение profile mounts, отсутствие видимости не подключённого host path, persistence и разделение managed HOME по canonical profile path/`--app-id`, mode/owner `0700`, а также отказ до payload для отсутствующего mount source. Отчёт сохраняется через общий dispatcher как `./tests/run.sh f04-mount-home`.
- Профили с сетью кроме `off` или опубликованными портами по-прежнему отклоняются до F05/F06. isobox не молча игнорирует заявленные разрешения и не запускает такой профиль с иной семантикой.
- GUI grants реализованы независимо. Wayland подключает только Unix socket из `WAYLAND_DISPLAY` в `XDG_RUNTIME_DIR` (или абсолютный `WAYLAND_DISPLAY`); в sandbox socket называется `wayland-0`. X11 поддерживает только локальный числовой Unix display, подключает его конкретный `/tmp/.X11-unix/XN` socket и при наличии только один Xauthority-файл read-only. TCP DISPLAY отклоняется. Audio использует обнаруженные локальные PipeWire/PulseAudio Unix sockets и/или `/dev/snd`; при использовании PulseAudio cookie-файл (если задан или найден) подключается отдельно read-only. Сетевой audio backend не пропускается. GPU подключает поддержанные `/dev/dri`, `/dev/kfd`, `/dev/nvidia*` nodes/directory через `--dev-bind`; отсутствие устройств блокирует запуск.
- `gui.desktop=true` подключает только локальный user session-bus socket и выставляет пересобранный `DBUS_SESSION_BUS_ADDRESS`; system bus не подключается. При grants=false host GUI environment очищено, `/run` и `/tmp` остаются приватными tmpfs, host sockets и GPU/audio devices не монтируются. isobox не вызывает portal API; при явном desktop grant приложение получает доступ к сервисам, зарегистрированным на host session bus, включая portal service, если он там доступен.
- GUI Unix sockets монтируются read-only в `/run/isobox` (или штатный X11 путь); этот runtime-каталог имеет режим `0700`. GPU/audio devices получают отдельные `--dev-bind`. При включённом grant, но отсутствии нужного локального socket/device или неподдерживаемом адресе, сборка sandbox завершается ошибкой до старта приложения.
- Runtime runner `tests/f04-sandbox/gui-grants/run.sh` создаёт изолированные synthetic Wayland/X11/PipeWire/PulseAudio/session-bus Unix servers и включает только один grant на профиль. App probe соединяется с подключёнными сокетами, проверяет нормализованные environment values, точный набор `/run/isobox`, read-only cookies и отсутствие system bus. Synthetic echo services проверяют только forwarding/access Unix socket, не полную совместимость протоколов Wayland/X11/audio/D-Bus. Отдельные отрицательные случаи проверяют path traversal в Wayland, TCP DISPLAY, не-Unix PulseAudio server и отсутствующий session bus; все должны отказать до marker приложения. При отсутствии поддержанного GPU runner требует соответствующий fail-closed отказ; при наличии проверяет видимый char device. Отчёт сохраняется через `./tests/run.sh f04-gui-grants`.
- Bubblewrap получает команду отдельными argv после `--`. `--new-session` отключает controlling-terminal ioctl TIOCSTI, который bwrap рекомендует блокировать seccomp-ом в обычной сессии. Для управления signal lifecycle isobox получает PID дочерней команды через `--json-status-fd`, пересылает INT/TERM/HUP/QUIT её process group, а `--die-with-parent` завершает sandbox при гибели isobox. bwrap возвращает shell-совместимый exit status, включая `128+signal`.
