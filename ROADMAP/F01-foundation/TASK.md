# F01 — Основа CLI

## Контекст

Создать каркас пустого Go-репозитория и стабильный CLI-вход. Не включать сетевые и sandbox-разрешения до появления соответствующих задач.

## Задачи

- [x] F01-T01 — Создать каркас модульного Go CLI с командой `isobox run`.
  - Шаги: определить минимальные внутренние интерфейсы; сохранить модуль `github.com/arwos/isobox`; добавить разбор profile/app-id/`--`/команды приложения; обеспечить сохранение аргументов приложения без переинтерпретации.
  - Приёмка: CLI показывает понятную ошибку при отсутствующей команде; команда и её аргументы отделены от флагов isobox. `--profile` стал необязательным в F02-T03.
- [x] F01-T02 — Показывать план запуска командой `isobox config`.
  - Шаги: принимать те же аргументы, что `run`; валидировать профиль, выполнять host preflight и отображать эффективные параметры запуска таблично без запуска приложения.
  - Приёмка: вывод содержит effective profile, приложение/аргументы и полный argv bubblewrap; команда не вызывает sandbox runner.
- [x] F01-T03 — Показывать активные запуски командой `isobox ps`.
  - Шаги: регистрировать PID приложения, app-id, исходную рабочую папку и режим сети на время запуска; читать PID usage из `/proc`; показывать результат таблицей.
  - Приёмка: колонками таблицы являются PID, app-id, рабочая папка запуска isobox, память, CPU и сетевой режим; запись удаляется после завершения приложения.
