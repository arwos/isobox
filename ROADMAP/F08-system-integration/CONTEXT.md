# F08 Контекст

- Системная интеграция необязательна; базовый rootless CLI не требует system service или root.
- Пользователь согласовал desktop launcher. Settings layers, ранее добавленные вместе с F08, впоследствии удалены; профиль по умолчанию описан в F02-T03.
- Security boundary задаётся профилем запуска и проверками F03–F07.
- Desktop entry: freedesktop Desktop Entry 1.5, `Type=Application`, статический `Exec` без shell и без динамических field codes; literal `%` экранируется как `%%`. Аргументы с зарезервированными символами заключаются в кавычки с двумя слоями escaping. Новые строки и другие control characters в значениях/аргументах отвергаются с ошибкой.
- Пользовательский systemd service хранится в `$XDG_CONFIG_HOME/systemd/user/isobox-<app-id>.service` (fallback `~/.config/systemd/user/`), имеет mode `0600` и marker ownership. `ExecStart` запускает абсолютный путь к isobox с `run --profile=... --app-id=...`; команда берётся из `profile.command`, пустая команда отклоняется при установке. Install вызывает `systemctl --user daemon-reload`, но не enable/start. Отдельные enable/disable переключают автозапуск в `default.target`, не меняя текущий статус сервиса; remove выполняет `disable --now`, затем удаляет unit и перезагружает manager. ExecStart escaping учитывает systemd `%`/`$` substitutions и запрещает control characters.
- Команды desktop launcher: `isobox integration desktop install --id=ID --name=NAME --profile=PATH --app-id=ID [--icon=ICON] [--terminal] -- APP [ARGS...]`; повторный install обновляет только launcher с маркером isobox. `isobox integration desktop remove --id=ID` удаляет только принадлежащий пользователю обычный файл с этим маркером.
- Launchers хранятся в `$XDG_DATA_HOME/applications/isobox-ID.desktop`; при пустом/относительном `XDG_DATA_HOME` используется `~/.local/share`. Создаваемые файлы имеют mode `0600`; каталог должен быть обычным каталогом пользователя и не быть доступен на запись другим пользователям/группам. Root и desktop portals не используются.
- Ранее реализованные системные и пользовательские `settings.unic` layers удалены решением F02-T03. Без `--profile` CLI использует только `~/.isobox/config/default.unic`; явный профиль не смешивается с ним. Первый `run` создаёт безопасный профиль, если файл отсутствует. Пользовательские systemd unit-файлы при этом остаются в стандартном XDG каталоге.

- Использованы официальные спецификации: [Desktop Entry 1.5](https://specifications.freedesktop.org/desktop-entry/latest-single/) и [XDG Base Directory](https://specifications.freedesktop.org/basedir/). `Exec` не запускается через shell; executable разрешается в абсолютный путь при создании launcher.
- Systemd unit формат и escaping сверяются с официальной документацией: [systemd.unit](https://freedesktop.org/software/systemd/man/latest/systemd.unit.html), [systemd.exec](https://freedesktop.org/software/systemd/man/latest/systemd.exec.html), [systemd.syntax](https://freedesktop.org/software/systemd/man/latest/systemd.syntax.html). `WantedBy=default.target` активен только после явного enable; install команды выполняют только daemon-reload.
- Историческая live-приёмка прошла в активной пользовательской X11-сессии: launcher лежал в XDG applications directory, `desktop-file-validate` принял его, а `gio launch` создал marker в app HOME через bwrap. Проверки settings layers относятся к прежней реализации и не подтверждают текущее поведение после F02-T03.
- Systemd unit содержит `[Install] WantedBy=default.target`, но install не включает его; пользователь отдельно выбирает enable/start. Remove сначала останавливает/отключает managed unit и только затем удаляет файл.
