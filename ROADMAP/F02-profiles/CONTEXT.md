# F02 Контекст

- Формат конфигурации — UNIC из `go.osspkg.com/unic`; профиль задаёт sandbox и может содержать argv-массив команды приложения по умолчанию.
- Значения по умолчанию пользователь переопределяет профилем; общий DNS может быть переопределён профилем.
- Безопасное значение по умолчанию для сети — `off`.
- Требуется типизированная Go-структура и последующая прикладная валидация, а не только успешный decode.
- Доступная инструкция по UNIC — `/home/user/.agents/skills/osspkg/osspkg-lib-unic-usage/SKILL.md`. Проверены `go.osspkg.com/unic` v1.0.2 и его исходники: `unic.Unmarshal(data, &cfg)` декодирует в переданную структуру; неизвестные поля внутри struct пропускаются, дубли одиночных полей decoder отклоняет, slices допускают повторные поля.
- Зависимость закреплена в `go.mod` как `go.osspkg.com/unic v1.0.2`; транзитивная `go.osspkg.com/bb v1.0.1` закреплена в `go.sum`.
- В `internal/profile/schema.go` определены Profile и Settings с `unic` tags. Профильное `command` хранит executable и аргументы как argv-массив без shell parsing. Пустой profile command допустим, если вызывающий передаст приложение после `--`; явная CLI-команда имеет приоритет. Профильный пустой network mode означает inherit; built-in Settings default — `off`.
- isobox полностью отключает IPv6 для sandbox-сети. Общий DNS хранится в Settings и может быть переопределён в профиле; разрешены только IPv4 адреса без порта. В `proxy` mode требуется эффективный DNS из профиля или Settings, чтобы дальнейший сетевой компонент не мог незаметно перейти на host DNS. В `direct` mode пустой DNS допускается, потому что режим прямо разрешает обычную IPv4 сеть.
- PortRule требует host address и описывает одиночный порт через `port` либо inclusive range через `port` + `end_port`; host и sandbox port одинаковы. Это низкорисковое допущение: пользователь отдельно не задавал перенумерацию портов.
- Лимиты типизированы явными единицами: `cpu_quota_percent` (100 = один логический CPU), `memory_bytes`, `process_count`, `open_files`; ноль означает отсутствие запроса лимита.
- GUI grants по умолчанию выключены; writable mounts требуют явного `read_only=false`, по умолчанию mount read-only.
- `profile.env` — явный map значений окружения приложения. Host environment остаётся очищенным; имена проверяются по ASCII-форме переменной окружения, NUL в значениях запрещён, а `HOME`, `PATH`, `PWD`, `TMPDIR`, `GOMAXPROCS` зарезервированы sandbox.
- `profile.path` — список дополнительных абсолютных нормализованных каталогов для `PATH`. Они располагаются перед встроенным sandbox `PATH`, чтобы профильные утилиты имели приоритет; host `PATH` не наследуется. Двоеточие запрещено в элементах из-за разделителя `PATH`.
- `profile.user` задаётся одной позиционной записью `user UID NAME;`, а `profile.group` — повторяемыми `group GID NAME;`. ID принимаются в диапазоне `0..4294967294`, имена — до 32 ASCII символов по шаблону `[a-z_][a-z0-9_-]*`; дубли group ID/name и malformed tuples отклоняются. Отсутствующие значения разрешаются в sandbox builder как host effective IDs с именем `isobox`.
- `DecodeProfile` и `DecodeSettings` сначала проверяют UNIC-поля по схеме из struct tags, затем вызывают go-unic, затем запускают прикладную валидацию. Так неизвестное security-поле не игнорируется decoder. Проверка ограничивает документ 1 MiB и вложенность 64 уровнями, принимает UTF-8/BOM, комментарии, кавычки, тройные backticks, блоки, списки и maps.
- Валидация проверяет версию; нормализованные абсолютные пути; запрещает root как HOME/mount source/target; требует source/target для каждого mount; обнаруживает повторные mount targets, некорректные network modes, IP DNS/bind addresses, proxy alias и proxy DNS, неверные порты/диапазоны/протоколы и пересекающиеся опубликованные порты. `profile.path` проверяется синтаксически; фактическая доступность каталогов зависит от root и profile mounts. Проверка путей синтаксическая: существование и пригодность host mount source проверит preflight при запуске.
- `ResolveProfile` материализует эффективный network mode и DNS. Пустой профильный mode наследует встроенный `off`. CLI валидирует выбранный профиль до запуска preflight. Без `--profile` `internal/integration.EnsureProfileForApp` при заданном app-id сначала ищет `~/.isobox/config/<app-id>.unic`; при отсутствии использует `~/.isobox/config/default.unic`, создавая безопасный файл при первом запуске. Без app-id используется только default. Каталоги профилей имеют режим `0700`, стартовый файл — `0600`. App-specific профиль применяется целиком, без merge; явный `--profile` обходит поиск. `XDG_CONFIG_HOME` не влияет на расположение этих профилей. Системные и пользовательские settings layers отключены.
- Для `proxy` alias и DNS обязательны в итоговой конфигурации. Alias допускается при отсутствующем profile mode, чтобы задать его для унаследованного proxy default. Alias вместе с явным `off`/`direct` отклоняется как конфликт.
