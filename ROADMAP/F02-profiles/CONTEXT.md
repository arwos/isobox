# F02 Контекст

- Формат конфигурации — UNIC из `go.osspkg.com/unic`; профиль задаёт sandbox, но не команду приложения.
- Значения по умолчанию пользователь переопределяет профилем; общий DNS может быть переопределён профилем.
- Безопасное значение по умолчанию для сети — `off`.
- Требуется типизированная Go-структура и последующая прикладная валидация, а не только успешный decode.
- Доступная локальная инструкция по UNIC — `/home/user/.agents/skills/osspkg/osspkg-lib-unic-usage/SKILL.md`. В ней отмечено, что неизвестные поля могут игнорироваться decoder; точный API нужно проверить по локальным примерам при реализации.
- Официальный репозиторий https://github.com/osspkg/go-unic не удалось открыть в ходе планирования (cache miss). Версию/API библиотеки не фиксировать по догадке; проверить при реализации.
- В `internal/profile/schema.go` определены Profile и Settings с `unic` tags. Профиль не содержит app command. Профильный пустой network mode означает inherit; built-in Settings default — `off`.
- Общий DNS хранится в Settings и может быть переопределён в профиле. Адрес DNS намеренно не зашит; F02-T02 должен решить поведение при пустом значении и не допустить DNS fallback в proxy mode.
- PortRule требует host address и описывает одиночный порт через `port` либо inclusive range через `port` + `end_port`; host и sandbox port одинаковы. Это низкорисковое допущение: пользователь отдельно не задавал перенумерацию портов.
- Лимиты типизированы явными единицами: `cpu_quota_percent` (100 = один логический CPU), `memory_bytes`, `process_count`, `open_files`; ноль означает отсутствие запроса лимита.
- GUI grants по умолчанию выключены; writable mounts требуют явного `read_only=false`, по умолчанию mount read-only.
- Теги и типы компилируются без зависимости go-unic; round-trip и реальные defaults через parser будут проверены в F02-T02 после подключения библиотеки.
