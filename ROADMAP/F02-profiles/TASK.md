# F02 — Профили UNIC

## Зависимости

- Требует: F01.
- Нужен для: F03, F04, F05, F06, F07, F08.

## Задачи

- [x] F02-T01 — Описать типизированную версионируемую схему профиля UNIC.
  - Шаги: задать структуру для mounts, сети, DNS, SOCKS alias, GUI-разрешений, опубликованных портов и лимитов; определить безопасные defaults.
  - Приёмка: профиль и общие defaults представлены типизированными версиями; сеть по умолчанию `off`; профиль может переопределить общий DNS; схема содержит proxy alias, который F02-T02 потребует для `proxy` mode; `HOME` может задавать путь на хосте.
- [x] F02-T02 — Реализовать разбор и fail-closed валидацию профиля и defaults.
  - Шаги: проверить версии, типы, обязательные поля, пути, режимы, диапазоны портов и внутренние инварианты; изучить поведение go-unic с неизвестными полями; не допускать, чтобы пропущенное или неизвестное security-поле молча меняло ограничения.
  - Приёмка: ошибки содержат путь/поле и исправление; невалидный профиль не передаётся в sandbox/network builder; приёмочная проверка покрывает пропущенные, неизвестные и конфликтующие поля.
- [x] F02-T03 — Создавать пользовательский профиль по умолчанию.
  - Шаги: при `run` без `--profile` использовать `~/.isobox/config/default.unic`, если не выбран app-specific профиль; при отсутствии создать безопасный профиль с сетью `off`; не смешивать его с явным профилем или системными settings.
  - Приёмка: флаг `--profile` необязателен; первый запуск без app-specific профиля создаёт валидный default с ограниченными правами, последующие запуски сохраняют пользовательский файл; явный профиль выбирается отдельно.
- [x] F02-T04 — Задавать переменные окружения приложения в профиле.
  - Шаги: добавить строковую map `env`, проверить имена/значения и запретить ключи, зарезервированные sandbox; передавать значения приложению после очистки host environment.
  - Приёмка: заданный `TERM` виден внутри приложения; отсутствующие переменные host не наследуются; некорректные имена и попытка переопределить sandbox-переменные отклоняются при валидации.
- [x] F02-T05 — Дополнять sandbox `PATH` каталогами из профиля.
  - Шаги: добавить список `path`; валидировать абсолютные нормализованные каталоги без `:`; добавлять их перед встроенным sandbox `PATH`, не наследуя host `PATH`.
  - Приёмка: bwrap получает профильные каталоги в начале `PATH`; пустой список сохраняет встроенный `PATH`; некорректные каталоги отклоняются до запуска.
- [x] F02-T06 — Выбирать профиль по app-id при отсутствии `--profile`.
  - Шаги: искать `<app-id>.unic` в каталоге `default.unic`; если app-specific профиль не найден, выбирать или создавать `default.unic`; явный `--profile` имеет приоритет.
  - Приёмка: app-specific профиль используется целиком; при его отсутствии используется default; без app-id используется default; явный профиль не делает автоматический поиск.
- [x] F02-T07 — Задавать команду приложения по умолчанию в профиле.
  - Шаги: добавить argv-массив `command`; использовать CLI-команду после `--` при её наличии, иначе профильную; при отсутствии обеих завершать запуск ошибкой.
  - Приёмка: профильная команда и аргументы запускаются без `--`; команда CLI заменяет профильную; пустые обе команды дают понятную ошибку; shell не запускается автоматически.
- [x] F02-T08 — Хранить профили в `~/.isobox/config/`.
  - Шаги: выбирать `<app-id>.unic` или `default.unic` из `~/.isobox/config/`, создавать приватные каталоги и не зависеть от `XDG_CONFIG_HOME`.
  - Приёмка: первый запуск создаёт `default.unic` с безопасной сетью `off`; app-specific профиль выбирается из того же каталога; каталог имеет режим `0700`, файл — `0600`.
- [x] F02-T09 — Задавать sandbox account names и guest IDs.
  - Шаги: добавить единственную запись `user UID NAME;` и повторяемые `group GID NAME;`; строго декодировать числовые ID и проверять имена/дубли.
  - Приёмка: malformed, out-of-range и conflicting group entries отклоняются до preflight; первая группа остаётся primary.
